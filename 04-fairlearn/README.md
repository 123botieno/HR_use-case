# 04 — Fairlearn: who gets shortlisted, and who gets missed?

## Where this fits

The job matching methods rank the same candidate pool separately for each vacancy and return five names per method. This stage asks whether shortlist exposure differs across groups, and, when independent suitability judgments are available, whether one group has more suitable candidates left out. It audits a completed run; it does not change rankings or decide who is suitable.

## The teaching scenario: inject and detect a controlled bias

The complete synthetic historical HR cohort and its four dimension-specific audit reports now live in [synthetic_hr_demo](synthetic_hr_demo/README.md), generated by [synthetic_hr.py](synthetic_hr.py). That dataset compares a qualification baseline with historical decisions generated from explicit gender, ethnicity, class, and geography penalties plus access proxies. Use it for the end-to-end multi-dimension lesson below.

Use the runnable scenario command below with a completed run. For each vacancy and method, it orders candidates by the baseline ranking and alternates mock labels beginning with Group B. This deliberately gives Group B one extra candidate when the top-five cutoff is odd, so the synthetic penalty produces a visible change in the demonstration. Do not call these candidates women and men: the groups are invented and convey nothing about candidates' actual gender.

The command creates a baseline copy and a teaching-only biased copy: it applies a score penalty to Group B large enough to move it below Group A within each vacancy and method, then recomputes ranks and top-five membership. The source run remains unchanged. It creates complete synthetic suitability labels by marking the ten highest baseline-ranked candidates suitable (or all candidates if the pool is smaller). The same labels apply to both groups. This deliberately controlled intervention provides an example of one way bias can enter and how an audit can reveal its effect.

The Fairlearn audit joins the mock group labels to the ranking by `jd_id,candidate_id`. `MetricFrame` calculates selection rate for each group, separately for each vacancy and method. A lower selection rate for Group B in the biased copy, compared with the original, is the injected disparity being detected. It is a test of the audit workflow, not evidence about real applicants or a real system's fairness.

To demonstrate missed suitable candidates as well, add complete, synthetic suitability labels for every audited candidate in the vacancy. Give both groups the same suitable-candidate pattern before injecting the penalty. With complete labels, the current audit also reports recall by group: the fraction of suitable candidates selected. A lower Group B recall means more suitable candidates from that mock group were missed. If labels are absent or incomplete, recall is omitted; do not treat unjudged candidates as unsuitable.

## Flow

1. Generate paired baseline and biased runs, mock group labels, and complete synthetic suitability labels.
2. Audit both runs using identical group labels and suitability labels.
3. Compare per-vacancy, per-method group counts, selection rates, and recall.
4. Discuss the result and limitations before drawing conclusions. Do not pool vacancies blindly: the comparison reports each vacancy separately.

The scenario command creates new teaching artifacts in its output directory. The audit command evaluates a run but does not modify it.

## What is measured

| Measure | What it means here | When it appears |
|---|---|---|
| Group count | Audited candidates in each group for one vacancy and method | When matching candidates have audit rows |
| Selection rate | Share of audited candidates in the group included in that method's top five | When group rows are available |
| Recall | Share of suitable audited candidates in the group included in the top five | Only when every audited candidate for that vacancy has a suitability label |
| Audit coverage | Share of the ranking with matching audit rows | Per vacancy and method |
| Small-sample flag | Whether group count meets the configured minimum (default 5) | Per group; a flag is not a statistical confidence interval |

Selection-rate differences show unequal shortlist exposure, not whether the selected people are qualified or the difference is justified. Recall requires independent suitability judgments. Fairlearn summarizes the metrics; people must decide which measures, tolerances, and follow-up actions fit the hiring context.

## Setup and use

Install the optional MLOps requirements and choose a completed run. Generate the scenario artifacts (this does not overwrite the source run):

```powershell
python 04-fairlearn/evaluate.py scenario --run runs/RUN_ID/run.json --output-dir runs/fairness-demo
```

This creates `baseline_run.json`, `biased_run.json`, `audit_groups.csv`, and `synthetic_judgments.csv`. Then run the paired Fairlearn evaluation:

```powershell
python 04-fairlearn/evaluate.py compare-synthetic --baseline runs/fairness-demo/baseline_run.json --biased runs/fairness-demo/biased_run.json --groups runs/fairness-demo/audit_groups.csv --judgments runs/fairness-demo/synthetic_judgments.csv --output runs/fairness-demo/comparison.json
```

The command writes separate `baseline_audit.json` and `biased_audit.json` files plus a `comparison.json` containing per-vacancy and per-method changes. Use `python 04-fairlearn/evaluate.py audit --run PATH --groups PATH --judgments PATH --output PATH` to audit another run. Omit `--judgments` when no appropriate labels exist. See [evaluate.py](evaluate.py) for the `MetricFrame` implementation.

## Code walkthrough

### Synthetic scenario

1. The `scenario` subcommand calls `make_synthetic_scenario()`, which loads the source run three times: original input, baseline copy, and biased copy.
2. It selects one baseline ranking per JD to assign deterministic alternating mock groups. It marks the top ten candidates from each JD-method ranking as synthetic suitable labels and writes one deduplicated audit and judgment row per JD/candidate.
3. For each biased ranking, it calculates a penalty large enough to move Group B scores below Group A scores, subtracts it, sorts again by score and candidate ID, and updates rank and shortlist flags.
4. It saves paired JSON runs plus `audit_groups.csv` and `synthetic_judgments.csv`. The source run is read-only.

### Fairlearn evaluation

1. `audit()` loads the run and audit CSV, rejects duplicate/empty group labels and IDs outside the run, then joins each ranked candidate by `(jd_id, candidate_id)`.
2. It creates one row per audited candidate with group, shortlist flag, and optional suitability label.
3. It always passes `selection_rate` to `MetricFrame`. It adds recall only when all audited candidates for that JD have labels.
4. It reads `MetricFrame.by_group`, adds counts and the minimum-size flag, and writes the per-JD/per-method JSON report. If a group has no suitable labels, recall is `null`.
5. `compare_synthetic()` calls `audit()` on baseline and biased runs with the same labels, then computes per-group rate changes and writes baseline audit, biased audit, and paired comparison artifacts.

Validation errors are raised for malformed audit mappings or judgments. Fairlearn or pandas import errors also stop the command. The sample-size flag is descriptive; this code does not calculate confidence intervals or significance tests.

## Discussion points

- Does the synthetic penalty lower Group B's shortlist rate consistently, or does the top-five cutoff make its effect vary by vacancy?
- If the two groups have the same synthetic suitability pattern, does the penalty also reduce Group B recall?
- Which is the right denominator for each question: all audited candidates for selection rate, or all suitable candidates for recall?
- What happens when audit coverage is incomplete, labels are missing, or a group has fewer than five people?
- How would a real audit obtain sensitive attributes appropriately, protect access to them, and keep them out of scoring?
- Who should set acceptable disparity thresholds and review a detected gap? Equal rates by themselves do not prove fairness.
- What follow-up would distinguish a scoring effect from differences in candidate pools, extraction quality, vacancy requirements, or recruiter judgments?

## Limits and interpretation

This exercise uses invented groups and an intentionally injected penalty. Its generated suitable labels are synthetic too: they mark the top ten baseline candidates in each ranking as suitable for demonstration, not based on recruiter review. It demonstrates that group metrics can capture a known difference in shortlist exposure and recall. It cannot establish that real candidates face this bias, validate a real-world fairness definition, identify the cause of an observed real gap, or justify mitigation.

The current audit does not estimate uncertainty, test counterfactual CVs, assess ranking quality by group beyond supported recall, or recommend automated mitigation. It uses only candidates present in the run and audit file. Do not infer gender or community membership from CVs. Real group analysis requires appropriately collected audit data and independent suitability judgments.
